# 竞品工程方法论蒸馏（内置经验包）

来源：2026-10-22 七项目专项调研（AstrBot / RuiC-oc-ferry / MiroFish / nanoMuse /
aoci-code / Filee / awesome-openclaw-skills）机制蒸馏。做能力探测、外部集成、
安全闸、长任务与多端功能时对照本包逐条自查；每条都是可执行的工程纪律，
不是背景知识。

## 一、模型能力探测：动作验证，不只验连通

连通（1 token 通）≠ 会干活。探测「模型是否真会执行工具」用随机令牌协议：下发一个
工具（如 report_token）+ 随机 token，令模型调用；带令牌的工具调用=全可用，只回文本=
「仅对话」要降权；调了工具但令牌不符换令牌重试一次；传输失败不改判定。判定带 TTL
缓存（免费池通道会换血），并按「探针模型」记录——换模型判定作废。

## 二、外部通道接管宿主配置：君子协定写入

工具要写宿主的配置文件（注册模型/通道）时守五条：只增删自己打过标记的条目、写前
备份、加锁、原子替换、内容没变不写盘；退出时把自己的条目摘干净。绝不全量重写他人
文件。

## 三、本机端点三防

本机转发/回调端口必做：绑 127.0.0.1、Bearer 鉴权、带 Origin 头一律 403（浏览器页面
发起的请求不可信）。动作执行权留在宿主，外部调用只能用结构化信封「表达」意图。

## 四、技能/插件包安检五类判据

ClawHub 生态实账：1.26 万技能近六成被过滤——疑似垃圾 / 重名与 typosquatting /
低质与描述不符 / 加密金融交易类 / 安全审计实锤恶意（373 个）。装前静态扫描+内容
指纹突变对账+装后冒烟验证是同一防线的产品化。

## 五、改码前后治理门

agent 改代码前后跑确定性对齐校验（verify/check）：索引/接口/约束是否仍与改动一致。
校验必须是纯函数、可 diff、随版本库走，不要藏在模型自评里。

## 六、外部引擎集成两纪律

按需下载（用到才装）+ 来源钉死在版本化清单（固定官方源，禁止运行期解析任意 URL）。
多步转换写成显式路由链（A→中间格式→B），每步可独立验证。

## 七、长任务三底线

token 预算必须先行（无预算的仿真引擎自承 High consumption，一轮烧 6-8 小时）；
agent 记忆勿绑外部 SaaS（断网即残、停服即丢）；小时级任务必须可断点续跑。算力
不够时优先考虑量化换速（4bit 换 11x 提速的实账），而不是硬扛。

## 八、多端/中继隐私边界

中继只传对话文字；文件与截图留在产生它们的设备上。危险动作（删除/发送/支付）
确认门支持按「单动作/会话/永远」记忆。跨设备路由用显式前缀（@设备名），不做
隐式推测。

## 九、账号池调度三纪律（magpie 蒸馏，2026-10-22）

配额调度要有时间维度：不是「死了才换」，是「窗口最快重置的先用」（smart）；
额度将尽分层控流（新会话 90% 停派、进行中的会话留守到 98% 排空）。会话粘性
优先于轮换：厂商 prompt cache 按「同模型+同前缀」命中（≥1024 token 才值得
保留），多轮重喂场景换模型=缓存作废全价重付，粘住直到确有理由才换。失败账号
垫底永不剔除：只剩它时照样试；429「限速但有余量」与「真耗尽」必须分开处置。
辅助三件：限流分类器失败不阻断（超时/冷却/缓存答案）；模型被厂商废弃（410）
自动隐藏、命中自动恢复；每请求记账带调用方归因。

## 十、宿主配置写盘台账（magpie 蒸馏，2026-10-22）

替宿主写配置文件的三件套：stash（被替换旧值入册，可一键还原）+ applied
（每个目标最后被写成什么/何时，可审计）+ 目标程序运行中拒绝写（它退出时
可能回写互相覆盖）。还原前校验「当前内容仍是我们最后一次写入的」才动手，
被人动过就拒绝——字节级还原语义，绝不在别人改动之上盲目覆盖；写盘走
原子替换+备份+旁路锁文件（崩溃残留超时强制接管）。

## 十一、Ghidra 五条工程纪律（2026-10-22 蒸馏）

①扩展元数据写在文件头注释（@category/@menupath），目录树/菜单/快捷键由元
数据自动生成——上架=拷一个文件；②指纹库设计：双粒度哈希（粗粒度抗环境漂
移+细粒度区分近似变体）+组合消歧（本体相同看引用/子项）+条目带
Name/Version/Variant 三元组分库，查重库跨任务持久复用；③重负载组件永远
独立子进程+显式协议，崩了由外层自动重生并重初始化，绝不进主进程；④升级
先备份旧数据、新旧版可并存（Save As）、客户端/服务端兼容矩阵在发布说明里
显式声明；⑤批量比对类工作台=多算法出候选→评分排序→人工裁决→批量应用，
进会话前先 validator 校验输入「够不够格」被比对。
