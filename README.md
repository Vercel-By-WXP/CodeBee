# Tutti · 多智能体编排台

> All agents, one score. —— 一声令下，众声齐奏。
> *Tutti*，音乐术语「全体齐奏」：指挥一挥手，所有声部同时进场。

本机多智能体编排系统：统一调度本机已装的 AI 编码 CLI（Codex CLI、Claude Code、
QwenCode、OpenCode、Aider……），提供 **目标 → 自动拆解 → 智能路由 → 执行 → 客观验证 → 跨厂商评审 → 自动修复/换将 → 汇总报告**
的完整闭环，附带智能体管理台（检测 / 安装 / 升级 / 模型配置 / 编排开关，安装失败时 AI 自动诊断修复）。

零第三方依赖：纯 Python 标准库（3.8+），本地 Web 界面，数据全部落盘可回放。

## 快速开始

```bat
start.bat
:: 或
python app\main.py --port 8765
```

自动打开 `http://127.0.0.1:8765`。首次运行会在 `data/` 下生成默认目录。

## 极简输入 + 会话延续

主表单只有 3 项：**类型、目标（一句话）、工作目录**（自动记住上次填写）。
标题自动取目标首行；其余（上下文/验证命令/编排模式/实现者/评审组/轮数/阈值）全部收进"高级选项"折叠，默认全智能无需改动。

**在已有会话上继续**：选择"Codex CLI 的会话"或"Claude Code 的会话"后，
Tutti 会扫描本地会话文件（`~/.codex/sessions`、`~/.claude/projects`）列出最近会话
（时间 / 项目 / 内容预览），选中一条后该任务就延续那个会话的完整上下文——
实现者自动指定为对应智能体，规划、实现、修复都在原会话上进行（评审仍用新鲜上下文避免偏见）。

## 两种任务

### 代码任务（实现 → 验证 → 评审 → 自动修复）
1. **实现**：实现者智能体（智能路由或手动指定）在工作目录内直接改代码；
2. **验证**：执行你配置的验证命令（pytest / build / lint……），确定性结果，不信任模型自评；
3. **评审**：优先派给**另一个厂商**的智能体（错误模式不相关，交叉评审信号最可靠），
   产出结构化 JSON（通过/评分/问题）；
4. **裁决与修复**：`验证通过 且 评审通过` 才算通过；不通过则自动修复循环（见"智能编排"）。

### 小说任务（草稿 → 多轮评审 → 发布门禁）
1. **起草**：作者智能体把稿件写入工作目录内的文件；
2. **评审**：多个评审智能体按维度（情节/人物/文笔/节奏/吸引力，可自定义）独立打分 + 提问题；
3. **修订**：任一维度低于阈值 → 汇总 major 意见回炉修订，进入下一轮；
4. **放行**：所有维度 ≥ 阈值才标记"达到发布标准"。

## 两种智能体

- **真实智能体**：来自 `data/catalog.json`，已安装且在管理页勾选"参与编排"的 CLI；
- **mock 智能体**（演示智能体 A/B）：内置、零消耗，用于验证流程 / 演示 / 回归测试。

mock 的评分逻辑是确定性的：第 1 轮故意略低于阈值、第 2 轮达标——用来验证发布门禁。

## 模型接入（API 供应商）

"模型接入"页 = **模型画廊** + 供应商配置 + CLI 绑定：

- **从 CCSwitch 导入**：一键读取 `~/.cc-switch/cc-switch.db`，导入全部 claude/codex
  供应商（地址/密钥/模型），**导入后自动拉取各供应商的可用模型列表**（后台并发，
  顺带带入 CCSwitch 的每百万 token 价格）；重复导入幂等；
- **模型画廊**：卡片网格展示全部模型，左侧按供应商/协议筛选，顶部搜索与启停筛选；
  每张卡片显示优先级（#1 最强）、价格、启停开关与 ▲▼ 调序按钮；
- **自动优先级**：新拉取的模型按名称启发式自动排序（pro/opus 强者靠前，
  mini/flash 便宜者靠后），手动调序后刷新会保留你的顺序；
- **运行时语义**：优先级第 1 = 默认模型；难度路由开启时困难任务用第 1、简单任务
  用末位（最省）；调用失败若是瞬态错误（503/无可用通道/限流）**自动降级到
  优先级列表的下一个模型**（最多 3 个）；
- **CLI 绑定**：claude 走 `ANTHROPIC_*` 环境变量、codex 走 `-c model_provider`
  覆盖，运行时注入不改写 CLI 全局配置；密钥只存本机 `data/models.json`；
- **安全**：拉取仅限用户自己配置的 http/https 地址，解析 IP 做边界校验、禁用
  重定向；内网自建网关（私网 IP）导入时自动放行 `allow_private`。

## 智能编排（默认模式）

任务表单默认"智能"模式：只填 **目标 + 工作目录**，其余由系统决定：

1. **规划**：最强可用智能体把目标拆成 ≤4 个有序子任务（JSON 计划，失败退化为单步模板），计划在运行详情可见；
2. **智能路由**：能力基线 × 历史胜率（过往 run 的 verdict 统计）打分选实现者；评审者强制跨厂商；每一步记录"为什么选它"；
3. **自动修复**：验证或评审不通过 → 问题清单自动发回实现者修复 → 重验证 → 重评审（至多 2 轮）；
4. **自动换将**：修复穷尽仍失败 → 自动切换到次优智能体全量重实现一次；
5. **报告**：结论、评分、路由依据、修复轮数、问题清单。

"手动"模式保留完整人工控制（指定实现者、评审组等），行为同 v1。

## 智能体管理

"智能体管理"页提供：

- **检测**：已装 / 未装、版本号（CLI `--version` / UWP AppxManifest / PowerShell）；
- **安装 / 升级**：执行 catalog 里配置的命令，日志落盘；**失败时 AI 自动诊断**——
  真实智能体读取失败日志 + 本机环境（node/npm/pnpm 有无）给出修正命令，
  只有命中白名单（`npm install` / `winget install` / `pip install` 前缀）才自动执行，否则留待人工确认；
- **模型配置**：两层——工具默认模型（写回各家配置文件，自动备份 `.bak`）与
  编排调用模型（`data/orchestration.json`，仅编排时通过 `-m/--model` 覆盖）；
- **编排开关**：决定哪些 CLI 参与任务路由。

安装命令不明的条目（Kimi Code / MiMo Code / Grok Build / Pi）：直接编辑
`data/catalog.json` 补上 `install` 字段，保存后点"重新加载 catalog"即可；
点"恢复默认 catalog"可回滚。

## 接入原理（已在本机实测）

| CLI | 无头调用 | 输出解析 |
|---|---|---|
| Codex CLI | `codex exec --skip-git-repo-check --json -s <sandbox>`（stdin 传提示词；.cmd 垫片经 `cmd /c`） | JSONL 事件流：`item.completed`=回答，`turn.completed`=token 用量 |
| Claude Code | `claude -p --output-format json`（stdin 传提示词；自动注入 `CLAUDE_CODE_GIT_BASH_PATH` 与输出上限） | 单个 JSON：`result` / `total_cost_usd` / `usage` |

所有子进程：并发读管道防死锁、超时/取消杀整棵进程树（`taskkill /T`）、stdout 全量落盘。

## 目录约定

```
data/
  catalog.json          智能体目录（可手动编辑）
  orchestration.json    编排偏好（启用/模型）
  tasks/*.json          任务
  runs/<run_id>/        每次运行：run.json、steps/*.log、report.md、error.log
```

安全约束（内置，勿绕过）：配置路径必须位于用户主目录内；任务工作目录必须是已存在的
绝对路径；稿件文件名消毒后限制在工作目录内；步骤日志读取禁止目录穿越。
