# CodeBee 页面风格与交互规范

版本：1.0，2026-09-24。适用于 `app/ui/`（index.html / app.js / style.css / board.*）与后续所有
前端改动。借鉴自 workdsh（techflag/workdsh）的 UI-DESIGN 体系，按 CodeBee 的无框架单页、
七皮肤、SVG 精灵图标实情改写。

## 0. 裁决链与同步义务

- 优先级：**用户纠偏 > 本规范 > 既有实现**。冲突时按此裁决，裁决后必须改规范。
- 每次用户纠偏（截图+一句话）落地时**三处同步**：本规范、实现代码、对应回归测试；
  只修当前页面不改规范=下次还会踩。
- 每次前端交付在 PR/提交说明里记录验收环境（见 §7），不达标要如实写明未达项。

## 1. 设计令牌契约（style.css）

换肤只是换变量值，布局与组件样式一律不认皮肤。当前令牌闭集：

| 令牌 | 语义 |
| --- | --- |
| `--bg` / `--sidebar` | 画布底 / 侧栏底（两层背景必须拉开层次） |
| `--panel` / `--panel2` | 卡片面 / 卡内嵌面（如输入条、工具行） |
| `--border` / `--border-strong` | 发丝线 / 强分隔（描边、悬停） |
| `--text` / `--muted` | 正文两级文字（够用则不加第三级） |
| `--accent` / `--accent2` | 主行动色 / 次行动色（图表双色） |
| `--ok` / `--warn` / `--bad` | 成功 / 警示 / 危险语义色 |
| `--mask` | 弹框遮罩（黑 50%，主题通用） |
| `--chip-queued-bg` `--log-bg` `--log-text` `--uc-*` `--ct-*` | 专用面（排队徽章/日志/用量图/代码高亮） |
| `--r-lg` `--r-md` `--r-sm` | 圆角三档 20/14/10px |
| `--mono` `--font-ui` `--font-display` | 等宽 / 界面 / 标题字体栈 |

规则：

1. **组件样式禁止硬编码颜色**。`rgba()`/十六进制只允许出现在：皮肤块（令牌定义本身）、
   `--shadow`、以及个别刻意主题无关的值（如开关白滑块 `#fff`）。语义 tint 一律
   `color-mix(in srgb, var(--ok) 14%, transparent)` 形态，禁止写死 Tailwind 色值。
2. 新皮肤块必须写全同一组变量（含日间版）；语义色可按既有惯例继承 `:root` 不覆盖。
3. 状态不得只靠颜色表达：必须同时有图标或文字（`--bad` 红底必须配「失败」字样或图标）。
4. 对比度：正文文字与背景 ≥ 4.5:1；`--muted` 用于辅助信息，不得用于关键操作提示。

## 2. 密度与控件基线

间距只用 4 的倍数，常用阶梯：**4 / 8 / 12 / 16 / 20 / 24 / 32**。

| 控件 | 尺寸 |
| --- | --- |
| 常规按钮（表单/工具栏） | 高 30–34px，紧凑 `.small` 高 26–28px；同组同高 |
| 弹框底部按钮 | 常规档；危险操作放最右且 `danger` 类 |
| 侧栏导航行 | 高 34–38px |
| 输入框/下拉 | 高 30–34px，与同行按钮同高 |
| 图标（`.ico` / `.ico-lg`） | 16 / 20px 两档；纯图标可点热区 ≥ 28×28px |
| 等宽正文（日志/代码） | 12–12.5px，行高 ≥ 1.5 |
| 界面正文 | 13–14.5px；辅助 11.5–12.5px |

桌面主档 1440×1000、副档 1920；移动 390 只保可用（侧栏抽屉化），不追求等价。

## 3. 图标纪律（SVG 精灵表）

1. 图标一律进 `#icon-sprite`（`<use href="#i-*">`），两档 `.ico/.ico-lg`；不再引入 emoji 或字符图标。
2. 语义选型：换图标要按含义挑（「卸载」≠「删除文件」），不因形状接近替代。
3. **纯图标按钮必须有可访问名称**（`aria-label` 或 `title`，二者其一）；装饰性图标加
   `aria-hidden="true"`。`tests/ui_audit.mjs` 有扫描断言，新增交互必须过。
4. 顶栏/导航图标与任务类型图标是两个资产语义，不混用。

## 4. 弹框骨架契约

标准弹框 = `openModal()` + `#modal` 骨架，结构四段固定：

```
.modal-wrap（遮罩+居中，z-index 200）
 └ .modal（max-width 620px / ask 440px；max-height calc(100vh - 48px)；纵向 flex）
    ├ .modal-head   固定标题 + 关闭钮（✕ 有 aria-label）
    ├ .modal-body   唯一滚动容器（overflow:auto）
    └ .modal-foot   钉底按钮排（.spacer 推右；危险操作最右）
```

规则：**头脚不滚、体才滚**；新弹框一律走 `openModal()`，不自建 absolute 布局。
既有的两个特例是批准的历史形态：`#file-pop`（文件内容弹窗，贴边全高）与
`#welcome`（帮助中心，左目录右内容）。可叠层：`#ask`(250) 在 `#modal`(200) 之上，
toast(300) 最顶。Esc 关闭与背景点击关闭必须至少有其一。

## 5. 状态全覆盖矩阵

每个页面/分区必须处理六态：**加载中 / 空 / 搜索无结果 / 正常 / 加载失败 / 无权限或离线**。
搜索无结果与空是两个态（文案不同：前者提示改关键词，后者提示去创建/拉取）。

每次写操作至少处理四态：**提交中（按钮禁用+文案变化）/ 失败（可重试）/ 成功（真实回执后）/
结果未知（提示用户自行核实，不得自动重复提交）**。

诚实标注四条（历史病灶都在这）：

1. 灰 ≠ 禁用：真禁用要有原因（`title` 说明为何不可点）。
2. 只有真实回执才显示成功，不制造成功响应（假排队/假新版本/aider 退出码 0 的教训）。
3. 示例数据必须标「示例数据」；规划中的功能标「未实现」，不留死按钮装可用。
4. 剥离/降级要如实告知（如市场安装剥离了脚本/钩子，装完点名文件清单）。

## 6. i18n 与文案

新 UI 文案一律中文原文当 key 走 `t()`，并在 `i18n.js` EN 表补译；跑 `tests/_chk_i18n_dups.mjs`
防重复键（后值静默覆盖）。模板字面量混 HTML 的片段不进字典（既有折中）。

## 7. 交付检查清单（每次前端交付过一遍）

1. **环境记录**：无头验证固定 `--force-device-scale-factor=1`、窗口 1440×950 或 1400×950、
   `prefers-reduced-motion` 显式钉死（动画断言时钉 false）。不同缩放/DPR 的截图不可比较。
2. 三档视口（1440 / 1920 / 390）无意外横向溢出。
3. 键盘可达：Tab 顺序、Enter 提交、Esc 关弹框；焦点可见。
4. 长文本：超长任务名/文件名截断省略，不撑破布局。
5. 空态与组合过滤：空目录+搜索+分类组合下有正确文案，不白屏。
6. 图标可访问名称扫描过（ui_audit）；i18n 重复键扫描过。
7. 涉及后端联动的，对应 Python 测试同批跑绿；测试服务用完按 PID 清场、验证端口释放。

## 8. 无头验证环境基线（tests/_ui_boot.mjs）

新 UI 测试一律用 `tests/_ui_boot.mjs` 起 Edge：DPR 钉 1、CDP 随机口（或 TUTTI_TEST_CDP 覆盖）、
启动行打印实际 `devicePixelRatio / innerWidth×innerHeight` 进结果头。改既有测试时顺手迁移，
不强求一次改完。
