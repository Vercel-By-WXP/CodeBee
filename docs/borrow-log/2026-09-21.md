## 10:30 用户点名：zai-org/ZCode 开源深挖

**结论**：功能面（桌面/Web/TUI/CLI）与 CodeBee 定位部分重叠但不可直接抄；真金是**治理体系**——机器可执行的架构基线守护。zcode CLI 本机无独立可执行（桌面宿主未进 PATH），按纪律不接 catalog。

**直接会话复查（用户追问）**：源码确认 Agent CLI 已有 `-p/--prompt`、`--output-format json|stream-json`、`--resume <session>`、`--continue`、`--cwd`，协议上可以成为 CodeBee 的直接会话智能体；但 `apps/zcode-cli/packages/cli/package.json` 当前为 `private: true`，本机 `Get-Command/where zcode` 均无结果，也没有可核验的公共 npm 安装链。接入三问：与现有 Codex/Claude/OpenCode 会话能力重合度高；源码可读但运行时是 Node 24 monorepo，不能作为轻量依赖直读；用户会搜 ZCode，但当前无法一键安装。结论：**先雷达跟踪，不造死链目录项**；官方发行稳定后按 `prompt/json/resume/cwd` 适配契约接入现有 runner。Apache-2.0 允许改造，但整仓复制必须携带 LICENSE、NOTICE/归属和修改声明，且会把第二套会话、权限、插件、升级系统引入 CodeBee，工程上不采纳。

**落地**：架构基线守护 Python 版三件套——
- `architecture-policy.json`：四层单向依赖（L0 基座 paths/settings/…/L3 入口 pipeline/main）+ maxFileLines 1200 + forbidCycles
- `scripts/architecture_check.py`：AST 建 import 图、三色 DFS 找环、层序单向检查、行数「历史最高」基线（存量千行文件不挡路、再涨一行就报）、`--changed` 只查变更文件、`--update-baseline` 刷新快照
- `.architecture-baseline.json`：首检 **136 条存量豁免**——5 条真实 import 环、123 条层序反向、8 个千行文件

**价值**：此前多代理并行写入的架构漂移（反向依赖、环、文件膨胀）全靠人眼和运气；此后每轮自动化提交前跑 `--changed`，漂移机器把关。开发过程抓到并修掉两个自检 bug：模块名归一（core.pipeline vs 裸名 manager）导致图断链漏环、lines 类豁免 text 含动态历史值导致比对失效。

**验证**：test_architecture_check.py 6 项（层序抓取/基线豁免/新环必抓/行数增长必抓/基线往返/真仓冒烟）+ 全量 unittest discover 1059 项全绿。

## 11:00 在线调度闭环与升级后自动生效

- **问题**：推荐路由此前主要依赖静态能力、人工优先级和历史胜负，缺少按任务类型/角色细分的真实成功率、延迟与成本反馈；运行详情能看到当次路由，却不能跨运行回放。npm 自升级完成后仍需手动重启，用户容易误以为新版本已生效。
- **落地**：用量台账新增 provider 维度，按精确维度→任务+角色→任务→全局逐级回退，成功率用 Beta(3,1) 平滑并计算 P50/P95 与平均成本；CLI 与模型链把这些指标作为软评分，健康、协议、密钥、显式绑定仍是硬约束，default 模型链继续保持人工顺序。新增脱敏调度事件台账与 `/api/dispatch/replay`，只保存 ID、候选、理由和终态，不保存 prompt、正文、密钥或文件内容。
- **流程**：代码任务先落确定性验证证据、再做模型评审；npm 升级成功、版本确实变化且无其他任务运行时自动重启服务，否则保留手动重启入口。
- **产品巡检**：修复桌宠拖动调用不存在的顶层窗口 `scan_dragto`、右键关闭未写回开关导致下次复活；端口清场只强制结束命令行精确匹配的旧 CodeBee，其他服务只报告占用，不发送关闭信号。
