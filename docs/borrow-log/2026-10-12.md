### 本轮落地优先级

1. **检查点事件化（P0）**：在现有文件快照上补 `tool_call_digest`、`conversation_ref`、`repropose_required`、`side_effects` 四个字段；恢复接口默认只恢复文件和对话引用，外部命令/MCP/网络动作必须重新审批。
2. **能力清单（P1）**：为每个 CLI/ACP/MCP 后端输出统一 manifest，至少包含 `transport`、`resume`、`sandbox`、`approval`、`mcp`、`platforms`、`model_tiers`；UI 与任务创建页直接读取 manifest。
3. **记忆治理（P1）**：项目记忆增加版本号、来源 run、变更 diff、注入预览和撤销；经验库与项目记忆保持独立预算，避免扩大上下文。
4. **外部评审状态机（P1）**：抽象 `requested -> assigned -> approved|changes_requested|dismissed|expired`，支持 webhook/禅道/未来 Slack 适配器共用，不把外部渠道写死在核心 pipeline。

### 不建议本轮接入

- Goose、Letta、Open SWE 的完整服务端/云端运行时：与 CodeBee 现有本地优先、供应链剥离和六源市场安全边界冲突，集成面大于收益。
- Gemini CLI 的 shadow Git 实现：借鉴数据模型即可；CodeBee 已有独立检查点目录和任务分支，不再引入第二套 Git 历史。
