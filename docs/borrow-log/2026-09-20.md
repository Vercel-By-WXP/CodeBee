## 七专项巡检

### A. token 节约

对照三段压缩、token_meter、预算熔断、cascade、经验召回、会话复用、diff-only 评审与 `_shrink_context_block`。发现默认 `compaction=false` 和 resume 直通路径没有累计真实 usage，令下一步预算熔断失效，已修并补单次/重试防重复测试。当前 exact cache 已实现但生产无 `cache_ttl` 调用；语义缓存缺失；压缩摘要仍只进审计 surface，真实 CLI 仍收到原 prompt。后续顺序：真实摘要接线→生产精确缓存→语义缓存评估。

### B. 插件市场

六源缓存正常：anthropic 296、anthropic-skills 5、claude-skills 99、clawhub 187、cocoloop 150、zcode 21。接入三问结论：候选与已有源重合高、部分需二跳才可读、用户主动搜索概率低，本轮不接新源；agency-agents-zh 等只蒸馏方法论。安全待办：39 个 wildcard skill 约 36.7 万字需独立 top-k 配额；重定向与非 GitHub `git clone` 仍可能绕过 SSRF 闸门。

### C. 任务类型

逐项检查 15 个菜单类型的名称、说明、引擎、参数和辅助信息。修复 review 自动路由把所有类型写死成 `novel`；为 11 个内容型流程补专属角色与成品契约；成本预估从前 10 个扩大到全部流程；修复类型切换 rubric 串值、流程保存丢 ID 和 direct 标签。禅道是转 `code` 的集成入口，不计菜单类型。

### D. 经验库

原 74 条中 serial_novel 47、code 26、通用 1，流程规范约 38%，其他类型仍偏空。已通过应用 API 入库两条：全类型巡检必须验证类型身份贯通；预算能力必须覆盖默认真实调用路径。知识库新增本轮 6 组竞品机制与复查记录，后续应按类型积累真实运行教训，避免继续向小说/代码偏科。

### E. 新 CLI 接入

`catalog.py` 运行时 11 个 CLI；本机除 OpenClaw 外其余 10 个已安装。DeepSeek-Reasonix、FuXi、Gitlawb、zero、Empryo/Embryo 均未安装，按“先实测再入目录”纪律不接，避免死链。clodex/acpx 的 headless 协议只进雷达。

### F. 禅道集成

定时扫描、产品/模块路由、建 code 任务、合并后 resolve、评论回写与群通知链路完整。本机 `poll_enabled=false`、产品档案为 0，`last_error=未配置产品档案`，因此无法声称已检查远端新 Bug 积压；先保持明确诊断。外部 Jira/Linear/bug triage 项目无超过现有闭环的新机制。

### G. 产品巡检

修复流程类型切换维度串值、保存/恢复后旧草稿遮蔽新定义、编辑预置流程误建副本、direct 显示成评审引擎、英文 direct 标签缺失和 README 类型/引擎口径。UI 回归使用随机端口与临时 `TUTTI_DATA`，不再碰真实实例。
