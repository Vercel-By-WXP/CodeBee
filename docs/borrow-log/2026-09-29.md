### fauxnix（20000419/fauxnix，565★，MIT/TS）——bash→PowerShell 确定性翻译层，深挖完成

- **架构**：parser→AST→generator→executor 四段，**运行时零 LLM**；每命令一个生成器产出自包含 PowerShell 块，遵守「fx 契约」（stdout 每命令一行字符串/stderr 走 [Console]::Error.WriteLine/退出码 $script:fx_exit/stdin 走 $input）；`-EncodedCommand`(UTF-16LE) 执行，超 32KB 限额自动落临时 .ps1。
- **量化基准（方法论金矿）**：7 模型三路对拍（裸 PowerShell vs fauxnix vs Git Bash）——裸写均值 9 个错误事件/163s，fauxnix 0 错误/66s，Git Bash 天花板 57s；最差模型差 3.1×。**结论：距真 bash 天花板仅 ~15%，且无需装 bash 工具链**。
- **覆盖**：109 命令与真 GNU coreutils 差分对拍（253 case 语料）；sed/awk 不支持的构造抛**命名错误**而非静默出错——与我们「宁拒勿垃圾」同调；附「诚实偏差清单」（export 语义/yes 65536 行上限/tail -f·heredoc 拒绝等逐条列明）。
- **与本项目关系**：我们 runner 在 Windows 执行 bash 风格命令走 cmd /c 垫片（windows-cli-shims 全家桶痛点），GBK 嗅探回退与我们的 _read_text_any_enc 同构（独立第三验证）；**我们已有 Git Bash 时它无增益（Git Bash 就是天花板），价值场景=无 Git Bash 的用户机**（npm 分发用户群）。
- **借鉴点**：①差分语料测试法（对拍真 coreutils——可给我们垫片层建同款语料）②命名错误原则印证 ③诚实偏差清单的文档标准 ④三轴量化基准法（工具调用数/错误事件/耗时）。
- **处置**：深挖清账；**不引入为 runner 依赖**（执行路径引入外部 npm 工具需装前扫描守卫先行）；差分测试法列「小而实」候选。

### hippo-memory（kitfunso/hippo-memory，763★，MIT/TS）——从结果中学习的 agent 记忆层，深挖完成

- **机制**：三层海马体模型——Buffer（会话内不衰减）→ Episodic（带时间戳默认衰减，**召回强化、错误粘滞**：错过的记忆半衰期变长）→ Semantic（hippo sleep 重放合并成稳定模式）；底层 SQLite+markdown 镜像（git 可追踪、人可读——与我们「文件真源」同哲学）。
- **诚实战术（罕见亮点）**：明说「实测有效的只有两条（错误粘滞+用则强化，机制审计 PR#232）；衰减与睡眠合并**未实测**、只是海马体灵感」——把「测过的」和「信了但没测的」分开写，正是我们执行标准「前后差异证据」纪律的同类。
- **与教训库对比**：同核（错误粘滞≈我们的失守沉底 karma；用则强化≈hits/seen 加权；md 镜像≈文件真源）。**真差量两条**：①弱记忆**时间衰减**（我们只沉底不衰减）②**周期性睡眠合并**（我们近似合并是写入时去重，非周期性重放压缩）③跨 agent 便携层（一份记忆伺候所有 CLI——我们单产品不需要）。
- **借鉴点**：弱教训时间衰减（小而实候选，karma 排序已有数据结构可挂）；睡眠合并（中大，待评估 ROI）。
- **处置**：深挖清账；两条候选进路线图，时间衰减优先。
