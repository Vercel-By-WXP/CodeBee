# DeepSeek / ZCODE 借鉴项后续落地

本轮实现上次报告余下三项：配置来源解释、插件宿主版本预检、Hook 失败诊断。沿用现有 Python 标准库架构，没有引入 Cordis、RPC 或额外后台服务。

## 配置来源解释

新任务保存有效参数的来源标签：任务请求、任务参数修改、流程、环境或默认值。只保留归一化后的参数，不保存原始请求、密钥或环境变量值。运行创建时固化这些参数与选择规则；以后编辑 task 不改写历史 run。没有来源记录的旧任务/运行返回 unknown，不拿当前配置补造历史事实。

CLI 与内置模型步骤在启动时保存脱敏的模型/厂商、绑定来源、思考档位、候选链和续接标志；收尾单独保存实际模型、厂商及各次尝试的成功状态。初始选择与降级结果分别保留。内置选择在真正解析时记录“任务厂商指定 / 编排者 / 厂商默认”，避免根据模型名字反推来源。自动推荐解释到绑定策略层，不声称揭示外部 CLI 内部的默认配置或所有排名权重。

- `GET /api/runs/{run_id}/config` 返回上述快照与步骤记录，复用 API 鉴权。
- 直连会话右侧“配置来源”可展开查看；其它流程同样通过 API 读取记录。
- 同时修复相关参数更新问题：只改 thinking 等字段时保留未提交的厂商、模型与 CLI；无效的模型 patch 在修改 mode 等字段前拒绝，避免失败请求留下部分更新。

## 插件兼容预检与更新

插件可在 `.codex-plugin/plugin.json` 声明可选宿主最低版本：

```json
{
  "codebee": {"min_version": "0.1.114"}
}
```

读取当前安装包 `package.json` 的版本，按严格 SemVer 比较（含预发布与 build metadata）。这里只支持完整最低版本，不接受范围表达式。未声明的旧插件继续兼容；声明非法时目录显示 blocked；已声明要求却读不到宿主版本时拒绝安装。发现结果和插件列表返回 compatibility 原因。

安装前、复制后、启用前、更新前和更新暂存副本发布前都会检查兼容性。权限沿用已有显式授权；更新不能静默扩大权限。运行时激活的插件 MCP 也会重查版本。

`POST /api/plugins/{plugin_id}/update` 与插件卡“更新”按钮从原安装源读取新版，不自动下载或安装其它来源。先在安装根目录内暂存并验证，再替换副本、登记新技能，保留原 enabled 和 grants。失败时恢复旧副本；无法恢复时保留备份并返回路径。新技能使用独立市场标记，避免准备更新时覆盖旧技能。成功后清理旧市场包；用户修改导致旧包不能清理时返回 cleanup_error 并在界面提示。

这不是跨进程、断电恢复的数据库事务；现有插件锁保护同一服务内的更新。原来源目录必须仍可读取。更新处理仅搬运文件和声明，不执行插件代码。源码插件升级与运行中的任务应安排在可控时机。

## Hook 失败诊断

保持 task_start/message_submit/run_end 三事件与 best-effort 行为。记录 succeeded / failed / timeout / spawn_failed / invalid_command，附退出码、单调时钟耗时、task/run id 与脱敏错误。Hook 非零退出的 stdout 不再注入模型；手动测试返回真实成功/失败，空 stdout 的成功仍算成功。

`GET /api/hooks/diagnostics` 返回最近 100 次调用和最多 50 个 Hook/事件的最近错误。记录持久化到数据目录的 `hook-diagnostics.json`，同一服务内加锁并原子替换文件。后续成功不抹掉最近错误。诊断写盘失败不改变 Hook 执行结果。`GET /api/hooks` 也附带这些记录，设置页显示对应 Hook 的最近调用和最近错误。

诊断不保存命令、stdin、stdout、任务正文或环境；stderr/异常会清除常见凭据形式及敏感环境变量值后截断。自定义 Hook 主动在 stderr 输出其它私密内容仍由其作者控制；诊断不是任意文本的完美脱敏器。这些 Hook 仍是旁路扩展，不成为执行前安全拦截器。

## 验证与共享工作区

专项覆盖：配置来源与运行隔离、真实 CLI/内置步骤记录（外部模型调用被替代）、模型降级结果、参数部分更新、API 鉴权/控制权、SemVer、复制后复检、启停保留、安装与更新失败回滚、越界路径拒绝、Hook 退出码/超时/并发写入/脱敏/存储失败。前端运行测试检查配置、错误与兼容性信息的 HTML 转义，以及更新按钮。
