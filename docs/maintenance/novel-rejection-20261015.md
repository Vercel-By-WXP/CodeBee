### 《神瞳鉴宝》：能力出现了，局面改变得不够

- 首章第119行：江野提出“封存……等警察，等检测”；第139行明确“瓶子假，不等于他清白”。
  困境具体，这是有效资产。但能力多次确认假货后，仍退回证据手续；开篇阅读回报容易变成“等待下一步核验”。
- 第二章从再看胶缝到称重、平台留存、工单复述、云备份、监控便签，多个动作服务同一种“留证”功能。
  这不是说取证不能写，而是应压缩重复功能，把篇幅给“发现迫使谁改变行动”。
- 首章第83行是“赔会的”，第133行是“赔出来的”。前一句语义需要读者补足；后一回重复强调经历，未增加同等分量的信息。
- 能力只能提供主角知道的线索，本来可形成有趣的信息差；目前专业结论、配角判断与主角观察较快互相确认，戏剧选择不足。

修改优先级：先重构事件与选择，再改指代、知识说明和情绪表达。统一引号有益于交付，但不足以解决文学文风。

### 《头七结账人》：亡者委托有氛围，人物为何非做不可还不够强

- 首章第51行：“不碍着。规程里没有这一问。”职业语气成立，但当改期触及母女关系时，情绪话题立即被办理规则收回。
  可保留克制，随后应让这个未追问的问题影响主角决定，而不是只增加登记项。
- 第163行明确主角想替收账人落笔是因为“想让这一页看着齐全”。触犯重要规则的动机主要是填完整表格，难以承载违规风险。
- 第173行又说“停电是不是那一笔招来的，他不知道”；后续确认不能代签，却没有同等清晰的现实损失，试探规则的后果偏轻。
- 第二章第41行，打印机卡纸“又带出一张旧的”关键结转单。人物尚未用具体行动逼出证据，线索依赖巧合，容易使对抗显得安排痕迹重。

修改优先级：把规则与真实欲望、关系代价绑定；让证据由人物行动取得；亡者设定要改变退款的解法与难题。

### 鉴宝：让“知道假货”变成必须付代价的选择

保留跑腿、当铺、父亲旧物与能力。首个事件集中在当场交割：对手要带走瓶子并迫使主角承担掉包责任；
能力只能辨出修补的先后，不能给出人名、录像或万能结论。主角发现关键证据藏在对方必须当众打开的夹层，
选择以自己仅有的押金承担一次合法检验费用，换取当场检验；他知道可能证明瓶子假，却未必证明自己没掉包。
对手为保住委托人秘密主动提出更诱人的私了，冲突由利益生长。
首个单元先兑现“这次交割的掉包责任不能落在主角身上”，再留下父亲修补手法为何出现在瓶上的问题。
能力规则和取证可信度需在章纲中补足，不能凭开眼就宣布司法定案。

试写片段：

>

>

复验问题：能力是否改变双方行动？主角是否承担可理解的代价？反应是否有利益动机？阶段结果是否确实发生？

### 亡者退款：让“这笔钱该不该收”成为关系冲突

保留亡者来电、全家福退款、母女隔阂和不能替收账人落名的规则。
先让主角找到许棠，得知她正靠这笔退款解决现实困难，却拒绝接受母亲借退款安排的和解。
主角若只交钱就完成账面任务，却违背委托中真正的愿望；若擅自代签，就让许棠背上她未同意的关系承诺。
主角冒失落笔应源自想保住她的具体利益或对师父旧事的错误判断，不能只因为表格没填满。
照相馆证据改由核对预约记录、追问实际拍摄对象、对手为保住商业信誉而退让取得，删除卡纸送关键证据。
首个单元兑现钱的去向与许棠自己的决定；母女矛盾可保留余波，不能靠追加新账无限拖延结果。

## 已实施的 CodeBee 优化

1. 立项和续写：明确首个单元的欲望、独有解法、代价、阶段答案；用事件可移植性检查标签式创新，压缩无功能手续循环。
2. 起草与返修：让能力进入行动、对手按利益反应；情感从矛盾欲望与关系产生，修订说明对应原问题、选择与后果。
3. 开篇重构：取消“只能强化钩子”的限制，注入作者背景与约束；在锁定设定确实无法解决时保留风险，不假称已修好。
4. 文本评审：五维每项均需送审正文逐字原文和解释，高分同样需要证据；排除章名、虚构引文、未读章节。
5. 开篇闸门：五维均需达内部阈值，不能以吸引力高分掩盖因果等短板；调用失败、无证据、分歧和返修复评失败均暂停扩写，保留稿件待重试。
6. 审计：保存送审章节、节选字数与全文字数、证据错误；提示实际已读范围，避免截断稿冒充通读。
7. 经验包：区分七猫原反馈与番茄未验证项；去掉将固定段数、情感特写、引号形式与平台拒稿直接等同的说法。

逐字证据验证只证明引用来自送审文本，不证明文学判断正确。内部阈值、两万字检查点均为项目流程，不能映射签约概率。

## 持续复盘闭环（2026-10-16）

本轮发现的系统缺口：通用经验库已有运行后总结，但“平台原话、送审版本、正文观察、
修改实验、改后效果”没有作为同一条因果假设保存。下次生成可能重复同类问题；内部
评分上涨也无法回答具体改动是否有效。现在新增独立复盘账本，不给无关教训统一奖惩。

当前最值得反复验证的三个原因：

1. **标签创新没有进入事件机制**：换职业、换名字、增加异常，都可能保留相同的
   “发现—记录—核验—等待”循环。检验能力/关系能否改变解法、选择与代价。
2. **人物利益和情绪被办理流程吞掉**：手续可以承载故事，但重复手续没有改变处境时，
   主角欲望、对手反应和关系变化就缺少篇幅。检验读者能否说清人物为何非做不可。
3. **打磨没有对照证据**：内部高分、格式合规、添加特写，都不能证明上述问题已解决。
   每轮只选一个主要问题，保留新旧可比小样，解释事件、选择或后果到底改变在哪里。

这些是报告已读部分支持的工作诊断，不能扩写为编辑额外意见或番茄审核原因。

### 如何继续积累

在仓库根目录执行（JSON 文件为 UTF-8；完整必填字段见模块校验器）：

```powershell
python -m app.core.novel_feedback list
python -m app.core.novel_feedback record feedback.json
python -m app.core.novel_feedback trial trial.json --feedback-id nf-qimao-shentong-20261015
```

`record` 可从内置案例复制字段；新反馈使用新 id，原话及来源不能用推测补齐。
`trial` 对象必填：`id/date/baseline_version/revision_version/change/method/read_scope/`
`baseline_excerpt/revision_excerpt/baseline_quote/revision_quote/assessment/result`。
`result` 仅允许 `improved/not_improved/inconclusive`。小样全文与摘要保存在本地账本，
原复验只追加不覆盖；同一进程内加锁并原子替换文件。CLI 应串行维护同一账本，
未实现跨进程写入事务，也未增加前端表单或自动抓取平台通知。

下一轮先完成一个首个故事单元的小样，按原反馈复读：保留有效生活细节，重做独有解法、
动机和结果；不能只润色句子。若结果仍不清楚，记 `inconclusive` 并调整方案；只有得到
新的真实平台通知后，才补充平台结论。两万字/三万字检查点仍按项目约定执行。
