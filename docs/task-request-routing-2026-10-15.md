# 自然语言直接新建 CodeBee 任务

用户反馈：在已有对话里发送“那在 E:\AI小说\保险调查员：每一场意外都有价格 下新建一个连载任务开始写前十章，要过七猫和番茄”，实际进入 CLI 续聊。期望是创建独立 CodeBee 连载任务。

## 实现

- `app/core/task_request.py`：确定性识别新建、创建、新开、另开、再开、另起、建立、发起、开设、开、建等明确命令，支持“请帮我”“在 CodeBee 里”等前缀。兼容全部已注册流程的名称和 ID（包括自定义流程）；通用任务按主要工作动作推断连载、小说、代码、调研、翻译、PPT、文章或文档，其他目标走独立直接执行任务。
- 提取命令前后的绝对目录、中文或数字章节数及每章字数；目录内部出现“下新建”“下写”等词时保留完整路径。子任务目标去掉创建任务的调度前缀，保留目录、附件及执行要求，避免执行模型递归创建任务。
- 操作方法问句、否定本次创建、仅举例、引用和附件预览不触发；工作目标本身含问句仍可新建。“不要新建其他任务”等约束随目标保留；“先不要执行”等暂缓要求保持对话路径，不自动起跑。
- `app/main.py`：在 `/chat`、`/messages` 进入信箱、取消或续跑之前创建任务；直接执行表单中的明确任务命令同样转换类型。复用现有创建、附件落盘、入队及失败收口流程。新目录来自用户本次明确选择；网络、禁用工具等执行限制继续继承，禁止创建任务的策略保持生效。
- `app/ui/app.js`、`app/ui/i18n.js`：对话、指挥和递话入口识别创建响应，显示创建成功并打开子任务，不误报为旧任务的新一轮或排队消息。
- `tests/test_task_request.py`：新增解析与入口集成回归，使用临时目录，验证运行中/已结束对话、创建失败、附件归属及策略继承。
- `tests/ui_task_request.mjs`、`.gitignore`：增加并纳入浏览器回归；隔离测试数据和用户主目录，模拟创建回复，不启动真实模型任务。

## 交付范围与经验

直接在主检出 `main` 开发，按用户要求仅提交、推送本次文件与共享文件中的自有修改，保留其他聊天的未完成改动。截图中的小说请求用于产品回归，没有创建真实写作任务；未发布或重启正在使用的服务。

跨执行引擎的产品动作应放在模型和 CLI 之前的统一请求边界处理；创建后的任务目标应描述实际工作，避免把“再创建任务”原样递交给执行模型。明确命令识别保持保守，其他表达继续使用既有对话路径。
