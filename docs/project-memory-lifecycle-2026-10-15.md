# 项目记忆恢复与刷新修复

项目记忆长期为空有两条主要原因：完成后的候选沉淀仅覆盖代码引擎，直连与写作引擎遗漏；旧版 `.codebee/project-memory.md` 没有迁移到治理界面读取的 JSONL 存储。

## 最终行为

- 所有编排引擎完成后生成并自动批准项目记忆；失败、取消、管理运行与 partial 不生成完成记忆。直连完成明确标注未经过独立验证或评审。
- 启动时迁移旧 Markdown 并回填历史完成运行。保留原文件、历史时间、审批和过期状态，重复执行不新增同一候选。
- 历史事实优先使用运行固化输入；任务移动到另一工作区后，不将旧运行记忆导入新项目。未记录的历史验证命令明确显示未知。
- 全量流式读取审批日志，避免较早的拒绝记录被后续回填覆盖；批量回填和项目索引按工作区缓存读取结果。
- 坏行、非法 UTF-8、非字符串来源及非法 Unicode 内容按记录隔离；格式异常内容不可批准或注入，邻近有效记忆仍能显示。
- 审批和反馈在进程内加锁，版本校验与追加写入组成同一临界区。
- 写作和直连引擎在基线检出后读取已批准、未过期且指纹有效的记忆。候选保存失败写入运行警告。
- 运行摘要发布持久化记忆 ID。详情及记忆中心在完成和持久化后刷新；同工作区其他任务的新记忆也刷新当前详情。
- 归档任务与运行支持记忆查看、手动刷新和注入预览；旧异步响应不会覆盖新页面结果，读取失败可重试。

- `node tests/test_project_memory_ui.mjs`：完成、持久化、跨任务刷新，归档查看/刷新/预览，工作区切换、失败重试和乱序响应均通过。
- `node --check app/ui/app.js` 和相关 Python 编译检查通过。
- 将暂存内容叠加到 HEAD 的临时测试快照，生命周期 26 项、直连引擎 8 项、附件上下文 1 项共 35 项：34 通过、1 项权限跳过；同样通过前端回归与语法检查。
- 使用上述测试快照和隔离数据目录启动完整 HTTP 服务，旧记录及完成运行各回填 1 条；非法来源与 Unicode 记录保留且不可注入，有效相邻记录仍可见。状态接口保留持久化记忆 ID。

真实服务仍有任务运行，因此未重启。已恢复的历史记忆可立即查看；新的后端自动沉淀与启动恢复逻辑在服务下次重启后生效。
